## 1. 产品简介

Doc Classifier 是一款基于 AI 的智能文档分类归档工具。它的核心价值是解决一个日常工作中非常普遍的痛点：当你面对一个堆满了各种混杂文件的文件夹——里面有会议纪要、项目报告、合同扫描件、Excel 数据表、PPT 演示文稿——你不得不一个一个打开阅读，然后手动判断它属于哪个类别，再拖到对应的文件夹里。这个过程既耗时又容易出错。

Doc Classifier 将这个过程自动化。它首先通过一个高性能的批量提取脚本，一次性读取所有文档的内容摘要（而不是逐个打开），然后由 AI 根据文档的内容特征自动判断分类，最后按照"类别 → 组织/项目 → 时间 → 文件"的层次结构将文件归档到整齐的目录中，并生成一份完整的索引报告。

整个工具的设计遵循三个原则。第一是**零配置**——你不需要手动安装 Python 包、不需要配置虚拟环境、不需要操心系统差异，脚本会自动处理一切。第二是**安全优先**——所有文件操作默认使用复制而非移动，分类方案必须经过你的确认才会执行，你的原始文件不会被意外删除或覆盖。第三是**跨平台**——同一套工具在 Windows、macOS 和 Linux 上都能正常运行，无需修改任何代码。

## 2. 快速开始（5 分钟上手）

如果你想以最快速度体验 Doc Classifier 的工作效果，只需要完成以下三步。后续章节会提供更详细的说明，但这三步足以让你完成一次完整的文档分类。

**第一步**，确保你的电脑上安装了 Python 3.10 或更高版本。在终端（macOS/Linux）或 命令提示符（Windows）中输入 `python --version` 或 `python3 --version` 确认版本号。如果没有安装 Python，请前往 https://www.python.org/downloads/ 下载安装。

**第二步**，将 `doc-classifier` 文件夹放到你的项目的 `.claude/skills/documents/` 路径下（如果你是在 Claude Code 中使用），或者放在任何你方便访问的位置。

**第三步**，运行批量提取脚本。打开终端，进入你的项目目录，执行以下命令：

```bash
python .claude/skills/documents/doc-classifier/scripts/batch_extract.py ./你的文档文件夹 --output /tmp/extracted.json
```

首次运行时，脚本会自动安装 uv 包管理器、创建虚拟环境、安装所有依赖。这个过程通常在 30 秒内完成（取决于网络速度）。安装完成后，脚本会自动开始扫描你指定的文件夹，提取所有文档的文本内容，并将结果保存为一个 JSON 文件。

之后，你就可以在 Claude Code 中对 AI 说"帮我整理文档"或者"请根据 extracted.json 的内容对文档进行分类"，AI 会读取提取结果，分析每个文档的内容，生成分类方案，等你确认后执行归档。

## 3. 安装与环境配置

### 3.1 前置要求

Doc Classifier 的唯一硬性要求是 **Python 3.10 或更高版本**。其他所有依赖（包括 uv 包管理器本身）都会在首次运行时自动安装。

你可以通过以下命令确认 Python 是否已安装以及版本是否满足要求：

```bash
# macOS / Linux
python3 --version

# Windows
python --version
```

如果显示的版本号低于 3.10，或者提示"command not found"，请前往 Python 官网下载安装：https://www.python.org/downloads/ 。Windows 用户在安装时请务必勾选"Add Python to PATH"选项。

### 3.2 获取 Doc Classifier

将整个 `doc-classifier` 文件夹放置到以下任一位置：

如果你在 **Claude Code** 中使用，推荐放在项目的 `.claude/skills/documents/doc-classifier/` 路径下，这样 Claude 能自动识别并触发这个技能。

如果你**独立使用**批量提取脚本（不通过 Claude），放在任何目录都可以，只要在运行命令时指定正确的脚本路径即可。

### 3.3 自动环境引导

这是推荐的使用方式，也是最简单的方式。你不需要手动做任何环境配置，只需直接运行批量提取脚本：

```bash
python scripts/batch_extract.py <源文件夹> --output extracted.json
```

脚本启动后会自动执行以下环境检查与配置（这个过程只在首次运行时发生，后续运行会直接跳过）：

脚本首先检测当前的 Python 解释器是否运行在 Doc Classifier 的专属虚拟环境中。如果不是（首次运行时一定不是），它会进入自引导流程。

接着，脚本在系统中搜索 `uv` 包管理器。它会检查 PATH 环境变量以及各平台的常见安装位置（Linux 的 `~/.local/bin`、macOS 的 `/opt/homebrew/bin`、Windows 的 `%LOCALAPPDATA%\uv`）。如果找不到 uv，脚本会自动安装它——在 Windows 上使用 PowerShell 安装脚本，在 macOS/Linux 上使用 curl 下载安装。

然后，脚本使用 uv 在 `doc-classifier/.venv/` 目录下创建一个 Python 虚拟环境。虚拟环境是一个隔离的 Python 运行空间，它安装的所有包不会影响你系统中的其他 Python 项目。

创建环境后，脚本通过 `uv pip install` 安装 7 个 Python 依赖包（pdfplumber、pypdf、pandas、openpyxl、xlrd、markitdown、chardet）。uv 的安装速度通常比 pip 快 10-100 倍。

最后，脚本使用虚拟环境中的 Python 重新执行自身，此时所有第三方库都可以正常导入，开始实际的文档提取工作。

### 3.4 手动环境引导

在某些场景下（比如你想在 IDE 中调试脚本，或者你需要先配置环境但稍后才执行提取），你可以选择手动引导环境。我们为三个平台分别提供了对应的引导脚本。

**Linux 和 macOS 用户**使用 Bash 脚本：

```bash
# 使用 source 命令可以创建环境后自动激活
source scripts/setup_env.sh

# 此时你已在虚拟环境中，可以直接运行 Python 脚本
python scripts/batch_extract.py ./docs --output extracted.json
```

**Windows PowerShell 用户**使用 PowerShell 脚本：

```powershell
# 执行环境引导
.\scripts\setup_env.ps1

# 手动激活虚拟环境
& .\.venv\Scripts\Activate.ps1

# 运行提取脚本
python .\scripts\batch_extract.py .\docs --output extracted.json
```

**Windows CMD 用户**使用批处理脚本：

```cmd
REM 执行环境引导（内部调用 PowerShell）
scripts\setup_env.bat

REM 手动激活虚拟环境
.venv\Scripts\activate.bat

REM 运行提取脚本
python scripts\batch_extract.py docs --output extracted.json
```

所有引导脚本都是幂等的（idempotent），也就是说重复执行不会产生任何副作用——如果环境已经存在，它会跳过创建步骤；如果依赖已经安装，它会跳过安装步骤。

### 3.5 可选加速工具

以下系统级工具不是必须的，但如果已经安装，批量提取脚本会优先使用它们以获得更快的提取速度。如果没有安装，脚本会自动回退到纯 Python 方案，功能不受影响，只是速度稍慢。

**pdftotext**（来自 poppler-utils）是提取 PDF 文本最快的工具。安装方式：Linux 上执行 `sudo apt install poppler-utils`，macOS 上执行 `brew install poppler`，Windows 上需要手动下载 poppler for Windows 并添加到 PATH。

**pandoc** 是一个万能的文档格式转换工具，Doc Classifier 用它来提取 Word 文档的纯文本。安装方式：Linux 上执行 `sudo apt install pandoc`，macOS 上执行 `brew install pandoc`，Windows 上执行 `winget install pandoc` 或从官网下载。

**LibreOffice** 仅在你需要处理旧版 `.doc` 格式时才有用，它的作用是将 `.doc` 转换为 `.docx` 再提取文本。如果你的文档都是 `.docx` 格式，则不需要安装它。安装方式：Linux 上执行 `sudo apt install libreoffice`，macOS 上执行 `brew install --cask libreoffice`，Windows 上从官网下载安装包。

## 4. 使用流程详解

### 4.1 工作流程总览

Doc Classifier 的完整工作流程分为六个阶段，形成一个从粗到细的信息处理管线：

```
确认范围 → 扫描提取 → AI 分类 → 确认方案 → 执行归档 → 生成索引
```

前两个阶段（确认范围和扫描提取）建立对文档集的全局认知。中间两个阶段（AI 分类和确认方案）完成分类决策。最后两个阶段（执行归档和生成索引）产出最终结果。整个过程中，人类在"确认方案"环节拥有最终决定权——AI 提出建议，你来拍板。

### 4.2 第一步：确认范围

使用前，你需要明确三个关键参数。

**源目录**指的是包含待整理文档的文件夹路径。它可以是一个平坦的目录（所有文件在同一层级），也可以包含子文件夹（脚本会递归扫描所有层级）。例如 `./raw-docs/`、`~/Downloads/项目资料/`、`D:\工作文件\待整理\`。

**输出根目录**指的是分类后的文件放在哪里。默认规则是在源目录的同级位置创建一个名为 `reference/` 的文件夹。例如，如果源目录是 `./raw-docs/`，输出目录就是 `./reference/`。你也可以指定任何其他位置。

**分类侧重**指的是你是想对所有文档进行全面分类，还是只关注特定类型。例如，如果你只关心会议纪要，AI 会专注于识别和细分会议纪要文档，其他类型的文件统一放入"其他"类别。这可以大幅减少你的审查工作量。

### 4.3 第二步：扫描与提取

这是整个流程中最关键的加速环节。运行批量提取脚本：

```bash
# 基本用法
python scripts/batch_extract.py ./raw-docs --output /tmp/extracted.json

# 指定每个文件提取的最大字符数（默认 2000）
python scripts/batch_extract.py ./raw-docs --output /tmp/extracted.json --max-chars 3000
```

脚本会递归扫描源目录下的所有文件，自动识别每个文件的类型，并使用对应的最快工具链提取文本摘要。提取的不是完整的文件内容，而是前 2000 个字符（默认值）——这对于判断文档类别来说完全足够，同时避免了处理大型文件时的性能问题。

脚本运行过程中会实时显示每个文件的处理状态：

```
📂 扫描目录: /Users/you/raw-docs
📄 发现文件: 35 个
  📖 周会纪要_0106.docx (docx)... ✅ (1856 字符)
  📖 月度财务报表.xlsx (xlsx)... ✅ (943 字符)
  📖 项目方案_v2.pdf (pdf)... ✅ (2000 字符)
  📖 合同扫描件.pdf (pdf)... ⚠️ (0 字符)

==================================================
✅ 提取完成!
   总文件数: 35
   docx: 15 个
   pdf: 8 个
   xlsx: 5 个
   pptx: 3 个
   image: 3 个
   text: 1 个
   成功: 33, 失败: 2
   输出: /tmp/extracted.json
```

提取完成后，所有信息都保存在一个结构化的 JSON 文件中。后续的 AI 分类步骤只需要读取这个 JSON 文件，不再需要反复打开原始文档。

### 4.4 第三步：AI 内容分析与分类

在 Claude Code 中，你可以直接对 AI 说类似以下的指令：

```
请根据 /tmp/extracted.json 的内容，对 ./raw-docs/ 下的文档进行分类整理。
分类后的文件放到 ./reference/ 目录下。
```

AI 会加载提取结果，分析每个文档的文本摘要，沿四个维度（类别、主体、时间、子类型）做出分类判断。对于无法确定类别的文件，AI 会将它放入"未分类"类别，而不是随意归类。

你也可以提供更具体的指令来引导分类：

```
只关注会议纪要类文档，按公司名称和月份分类。其他类型的文件先不用管。
```

```
这批文件都是 XYZ 项目的，请按文档类型和项目阶段分类。
```

### 4.5 第四步：确认分类方案

AI 完成分析后，会向你展示一个完整的分类方案，以目录树的形式呈现：

```
reference/
├── 会议纪要/
│   ├── ABC科技公司/
│   │   ├── 2025-01/
│   │   │   ├── 第1周_周会纪要.docx
│   │   │   ├── 第2周_周会纪要.docx
│   │   │   └── 附件/
│   │   │       └── 周会数据汇总.xlsx
│   │   └── 2025-02/
│   │       └── 需求评审会纪要.docx
│   └── XYZ项目组/
│       └── 2025-01/
│           └── 项目启动会纪要.docx
├── 项目文档/
│   └── XYZ项目/
│       ├── 需求规格说明书_v2.docx
│       └── 附件/
│           └── 数据模型.xlsx
├── 未分类/
│   └── readme.txt
└── INDEX.md
```

**这是你做最终决策的环节。** 在你明确表示"确认"或"可以执行"之前，AI 不会移动或复制任何文件。你可以在这个环节要求调整，比如：

```
把"需求规格说明书_v2.docx"从项目文档移到会议纪要下面，它其实是需求评审会的配套文档。
```

```
"未分类"里的 readme.txt 不需要管，直接从方案中去掉。
```

### 4.6 第五步：执行归档

确认方案后，AI 会创建目录结构并复制文件。默认使用 `cp`（复制）而非 `mv`（移动），这意味着你的原始文件不会被删除或改变。你可以在确认归档结果没问题之后，自行决定是否删除原始文件。

如果你确认想直接移动文件（而非复制），可以在确认方案时明确告知 AI：

```
确认方案，请使用移动而不是复制。
```

### 4.7 第六步：索引报告

归档完成后，AI 会在输出根目录下生成一份 `INDEX.md` 文件，它是整个文档库的目录导航。索引报告包含四个部分：文件统计概览（总数及各类别数量）、分类明细表（每个文件的文件名、日期和一句话内容摘要）、附件关联表（每个附件归属于哪个主文档）、以及未分类文件清单和未能分类的原因。

这份索引报告本身就是一个有价值的交付物——你可以把它分享给同事，让他们快速了解这批文档的全貌，而不需要逐个打开文件。

## 5. 分类规则详解

### 5.1 分类维度

Doc Classifier 沿四个维度对文档进行分类，每个维度解决一个不同的问题。

**类别维度**回答的是"这个文档是什么性质的？"——是会议纪要、项目报告、合同协议还是数据报表？这是最核心的分类维度，决定了文件放在哪个大类文件夹下。

**主体维度**回答的是"这个文档跟谁有关？"——属于哪个公司、哪个部门或哪个项目？这决定了大类文件夹下的子文件夹结构。

**时间维度**回答的是"这个文档是什么时候的？"——属于哪年哪月？这决定了最深一层的文件夹（如 `2025-01/`）。时间的提取优先看文件名中的日期信息（如 `周会纪要_20250106.docx`），其次看文档内容中提到的日期，最后使用文件的修改时间。

**子类型维度**回答的是"这是这个类别下的哪种具体类型？"——比如会议纪要下的"周会"和"专题会议"是两种不同的子类型。子类型信息通常体现在文件名或索引报告中，而不一定对应独立的文件夹层级。

### 5.2 内置文档类别

Doc Classifier 预定义了 8 个常见的文档类别，每个类别有明确的识别特征。这些类别覆盖了大多数办公场景，AI 会根据文档内容的结构和关键词自动匹配最合适的类别。

**会议纪要**类的典型特征是包含参会人员名单、会议时间、议题列表、讨论内容、决议事项和待办任务。它的子类型包括周会纪要、月会纪要、专题会议、评审会和项目启动会。

**项目文档**类的典型特征是围绕某个特定项目展开，包含项目目标、里程碑、任务分解、进度状态等信息。它的子类型按项目阶段划分，包括立项报告、需求规格、设计文档、测试报告和验收报告。

**合同协议**类的典型特征是包含法律条款、甲乙方信息、权利义务、签署日期和合同金额。它的子类型包括采购合同、服务协议、保密协议和框架协议。

**报告类**的典型特征是对一段时间或一个主题的总结分析，通常包含数据、图表和结论。它的子类型按周期划分，包括日报、周报、月报、季报和年报。

**技术方案**类的典型特征是对技术问题的解决路径描述，包含架构图、技术选型、实施步骤和风险评估。

**通知公告**类的典型特征是单向传达信息，包含发文单位、发文日期、适用范围和执行要求。

**培训材料**类通常以 PPT 形式存在，包含课程大纲、知识点讲解、练习题目。

**数据报表**类主要是 Excel 文件，包含结构化的数据表格，用于统计分析、财务核算或业务监控。

如果一个文档不能明确归入以上任何类别，它会被放入**未分类**。

### 5.3 附件识别与归属

Doc Classifier 会自动识别哪些文件是其他文档的"附件"，并将它们放在对应分类的 `附件/` 子文件夹中，而不是单独分类。

以下类型的文件会被考虑为附件候选：图片文件（PNG、JPG、GIF 等）、压缩包（ZIP、RAR、7Z 等）、文件名中包含"附件"字样的文件、以及与另一个文档文件名高度关联的文件（比如 `Q3财务分析_附件1.xlsx` 很明显是 `Q3财务分析报告.docx` 的附件）。

附件归属的判断逻辑是：首先检查文件名是否有关联（共享前缀或关键词），其次检查是否有主文档在内容中提到了这个文件名，最后综合考虑时间和主题的关联性。

### 5.4 目录层级自适应

目录结构的深度不是固定的，而是根据实际文件数量自动调整。这避免了一种常见的问题——建了很深的文件夹层级，结果每个末端文件夹里只有一两个文件，看起来比扁平结构还难找。

具体的自适应规则是：如果某个类别下的文件少于 5 个，就省略月份层级（直接把文件放在主体文件夹下）；如果只有一个主体（比如所有文件都属于同一个项目），就省略主体层级；如果无法从文档中识别出时间信息，就省略时间层级。

## 6. 支持的文件格式

Doc Classifier 能处理办公环境中最常见的文件格式。每种格式都有对应的提取策略和备选方案，确保在不同环境下都能工作。

| 格式 | 扩展名 | 提取方式 | 提取内容 |
|------|--------|---------|---------|
| PDF | .pdf | pdftotext → pdfplumber | 文本内容（前 10 页） |
| Word 新版 | .docx | pandoc → 解压读 XML | 全文文本 |
| Word 旧版 | .doc | LibreOffice 转换 → pandoc | 全文文本 |
| Excel 新版 | .xlsx | pandas + openpyxl | Sheet 名、列名、前 10 行 |
| Excel 旧版 | .xls | pandas + xlrd | Sheet 名、列名、前 10 行 |
| CSV/TSV | .csv / .tsv | pandas | 列名、前 20 行 |
| PowerPoint | .pptx | markitdown → 解压读 XML | 各幻灯片文本 |
| Markdown | .md | 直接读取 | 全文（前 2000 字符） |
| 纯文本 | .txt | 直接读取（自动检测编码） | 全文（前 2000 字符） |
| RTF | .rtf | 直接读取 | 全文（前 2000 字符） |
| 图片 | .png/.jpg/.gif 等 | 仅记录元信息 | 标记为附件候选 |
| 压缩包 | .zip/.rar/.7z 等 | 列出内部文件名 | 文件清单 |

表格中的"→"表示优先使用左侧工具，失败后自动回退到右侧工具。所有文本类文件支持自动编码检测（UTF-8、GBK、GB2312 等），在中文 Windows 环境下尤其有用。

## 7. 跨平台使用指南

### 7.1 Windows 用户

**推荐方式**：直接运行 Python 脚本，脚本会自动处理一切。

```powershell
# PowerShell（推荐）
python .\scripts\batch_extract.py .\docs --output extracted.json
```

```cmd
REM CMD
python scripts\batch_extract.py docs --output extracted.json
```

**手动环境引导**（如果需要）：

```powershell
# PowerShell
.\scripts\setup_env.ps1
```

```cmd
REM CMD
scripts\setup_env.bat
```

**Windows 特有注意事项**：

Windows 10/11 通常预装了 Python 的 "App Installer" 别名，输入 `python` 会跳转到 Microsoft Store。如果遇到这种情况，请在"设置 → 应用 → 应用执行别名"中关闭 Python 的别名，然后从官网安装 Python。

如果 PowerShell 提示"无法加载脚本，因为在此系统上禁止运行脚本"，这是 Windows 的执行策略限制。你可以在 PowerShell 中执行 `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` 来允许运行本地脚本。

中文 Windows 上的文件编码通常是 GBK 而非 UTF-8。Doc Classifier 使用 `chardet` 自动检测编码，能正确处理这种情况，无需手动转换。

### 7.2 macOS 用户

**推荐方式**：

```bash
python3 scripts/batch_extract.py ./docs --output extracted.json
```

注意使用 `python3` 而非 `python`——macOS 可能将 `python` 命令指向旧版 Python 2（在较老的系统上）。

**手动环境引导**：

```bash
source scripts/setup_env.sh
```

**macOS 特有注意事项**：

如果你使用 Homebrew，可以通过 `brew install uv` 安装 uv，也可以让脚本自动安装。

Apple Silicon Mac（M1/M2/M3/M4）和 Intel Mac 的 Homebrew 安装路径不同。Apple Silicon 在 `/opt/homebrew/bin`，Intel 在 `/usr/local/bin`。Doc Classifier 的脚本已经处理了这两种路径，你不需要做任何额外配置。

如果你安装了 LibreOffice，它的路径是 `/Applications/LibreOffice.app/Contents/MacOS/soffice`。脚本会自动在这个路径搜索，不需要你手动添加到 PATH。

### 7.3 Linux 用户

**推荐方式**：

```bash
python3 scripts/batch_extract.py ./docs --output extracted.json
```

**手动环境引导**：

```bash
source scripts/setup_env.sh
```

**Linux 特有注意事项**：

某些 Linux 发行版（如 Ubuntu）的 Python 包不含 `venv` 模块。如果遇到"No module named venv"错误，需要安装它：`sudo apt install python3-venv`。安装后 uv 就能正常创建虚拟环境了。

如果你想一次性安装所有可选加速工具（推荐），可以在 Ubuntu/Debian 上执行 `sudo apt install poppler-utils pandoc`。

## 8. 常见问题（FAQ）

**Q：Doc Classifier 会删除或修改我的原始文件吗？**

不会。所有文件操作默认使用复制（`cp`），你的原始文件不会受到任何影响。分类方案也必须经过你的明确确认才会执行。只有在你明确要求"使用移动而不是复制"时，才会使用 `mv` 命令。

**Q：首次运行需要联网吗？**

是的，首次运行时脚本需要从网络下载 uv 和 Python 依赖包。之后 uv 会缓存所有已安装的包，离线环境下可以直接使用（前提是虚拟环境已经创建好）。

**Q：处理 100 个文件大概需要多长时间？**

批量提取脚本处理 100 个混合格式文件通常在 1-3 分钟内完成（取决于文件大小和类型）。PDF 和旧版 .doc 文件会慢一些，纯文本和 Markdown 几乎瞬间完成。

**Q：可以处理扫描版的 PDF 吗？**

目前版本不支持 OCR（光学字符识别）。如果一个 PDF 是扫描图片而非文本流，提取脚本会报告"提取 0 字符"，该文件会被标记为"需 OCR"并归入未分类。未来版本可能会集成 OCR 能力。

**Q：可以自定义分类类别吗？**

可以。在向 AI 发出分类指令时，你可以明确指定自己的分类体系。例如：

```
请按以下类别分类：投标文件、中标通知、合同签署、验收报告、付款凭证。
不在这些类别内的文件放入"其他"。
```

AI 会按照你指定的类别来分类，而不是使用内置的默认类别。

**Q：文件名是乱码怎么办？**

这通常是编码问题，在中文 Windows 环境下较常见。Doc Classifier 使用 `chardet` 自动检测文件编码。如果文件名本身是乱码（而非文件内容乱码），说明文件在不同操作系统之间传输时编码发生了混乱。此时 Doc Classifier 仍然可以正常读取文件内容并根据内容分类，但文件名不会被自动修复。

**Q：`.venv` 文件夹需要提交到 Git 吗？**

不需要。`.venv` 是虚拟环境目录，应该在 `.gitignore` 中排除。任何人拿到代码后运行一次脚本就会自动重新创建虚拟环境。

## 9. 故障排除

**问题：运行脚本时提示 "python: command not found"**

这说明 Python 没有安装或没有添加到 PATH。在 macOS/Linux 上尝试 `python3` 代替 `python`。在 Windows 上确认安装 Python 时勾选了"Add Python to PATH"，或者使用完整路径如 `C:\Python312\python.exe`。

**问题：提示 "uv: command not found" 且自动安装失败**

这可能是因为网络问题或权限限制。你可以手动安装 uv：访问 https://docs.astral.sh/uv/getting-started/installation/ 按照官方说明安装。安装后确认 `uv --version` 能正常输出。

**问题：PowerShell 提示"禁止运行脚本"**

执行以下命令放开当前用户的脚本执行策略：

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

**问题：PDF 提取出来是空的（0 字符）**

这通常有两种原因。第一种是 PDF 是扫描图片（非文字流），需要 OCR 才能提取文本，当前版本不支持。第二种是 PDF 被加密了，需要密码才能读取。两种情况下文件都会被归入"未分类"并在索引中注明原因。

**问题：Excel 文件读取失败**

如果是 `.xls`（旧版格式），确保 `xlrd` 包已正确安装（自引导机制会自动安装）。如果 Excel 文件有密码保护，则无法读取，文件会被归入"未分类"。如果 `.xlsx` 文件损坏（无法作为 ZIP 打开），也会读取失败。

**问题：旧版 .doc 文件无法处理**

需要安装 LibreOffice（参见 3.5 节）。如果不想安装 LibreOffice，这些 `.doc` 文件会被标记为"提取失败"并归入未分类。你也可以先用 Word 或 WPS 手动将它们另存为 `.docx` 格式。

**问题：虚拟环境创建失败**

确认 Python 版本 ≥ 3.10。在 Ubuntu 上可能需要安装 `python3-venv` 包：`sudo apt install python3-venv`。如果磁盘空间不足也可能导致创建失败，虚拟环境大约需要 200MB 空间。

## 10. 文件结构参考

Doc Classifier 的完整文件结构如下。其中 `.venv/` 目录在首次运行时自动生成，不需要手动创建，也不应提交到版本控制。

```
doc-classifier/
│
├── SKILL.md                     # AI 技能指令文件（Claude Code 用）
├── pyproject.toml               # Python 依赖声明（uv 读取）
│
├── scripts/
│   ├── batch_extract.py         # 核心脚本：批量文档文本提取（内置跨平台自引导）
│   ├── setup_env.sh             # 环境引导 — Linux / macOS（Bash）
│   ├── setup_env.ps1            # 环境引导 — Windows（PowerShell）
│   └── setup_env.bat            # 环境引导 — Windows（CMD，调用 ps1）
│
└── .venv/                       # 虚拟环境（自动生成，勿提交 Git）
    ├── bin/                     # Linux/macOS 可执行文件
    │   └── python               # 虚拟环境 Python
    ├── Scripts/                 # Windows 可执行文件
    │   └── python.exe           # 虚拟环境 Python
    └── lib/                     # 已安装的 Python 包
```

归档完成后，输出目录的结构遵循以下模式：

```
reference/                       # 输出根目录（默认名称）
├── {类别}/                      # 第一层：文档类别
│   ├── {主体}/                  # 第二层：公司/部门/项目
│   │   ├── {YYYY-MM}/          # 第三层：年月
│   │   │   ├── 文档.docx       # 文档文件
│   │   │   └── 附件/           # 附件子文件夹
│   │   │       └── 数据.xlsx
│   │   └── ...
│   └── ...
├── 未分类/                      # 无法确定类别的文件
│   └── ...
└── INDEX.md                     # 索引报告
```

## 11. 安全说明

Doc Classifier 在设计上将数据安全作为核心考量。以下是你需要了解的安全相关事项。

**文件操作安全**：所有文件操作默认使用复制（`cp`）而非移动（`mv`），确保原始文件不会被意外删除。分类方案必须经过用户明确确认后才会执行。如果出现文件名冲突，脚本会自动添加序号后缀而不是覆盖已有文件。

**环境隔离**：所有 Python 依赖都安装在独立的虚拟环境（`.venv/`）中，不会影响系统的 Python 环境或其他项目。虚拟环境可以随时删除重建，不会留下任何系统级的残留。

**数据隐私**：批量提取脚本在本地运行，提取的文本内容保存为本地 JSON 文件。如果你在 Claude Code 中使用 AI 进行分类分析，文档的文本摘要会被发送到 AI 服务。请确保你的文档不包含不宜分享的敏感信息，或者在提取时使用 `--max-chars` 参数限制提取的文本量。

**权限控制**：脚本不会访问指定源目录之外的任何文件。它也不会修改原始文件的内容或属性——只执行读取和复制操作。
